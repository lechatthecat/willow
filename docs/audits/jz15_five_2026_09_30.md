# Five language fixes, 2026-09-30

## String syntax

An ordinary double-quoted string may span physical source lines. A raw newline
inside the quotes becomes a newline in the value. Existing escapes, including
`\n` and `\"`, retain their meaning. The closing `"` is still required; an
unclosed string reports E0051 at its opening quote. For example:

```willow
println("first line
second line");
```

## Work and verification perspectives

The focused tests and runnable `example/compound_and_multiline.wi` cover:

1. E2001 on a function parameter labels `Array<i64>`.
2. E2001 on a constructor parameter labels `Array<i64>`.
3. E2002 on a method parameter labels `Map<i64, i64>`.
4. A raw newline is retained in a string token.
5. Lexing resumes at the correct line after that token.
6. An unclosed multi-line string labels its opening quote.
7. An escaped newline remains available alongside raw newlines.
8. A multi-line string compiles and prints its exact bytes.
9. `+=` works on a local.
10. `-=` works on a local.
11. `*=` works on a local.
12. `/=` works on a local.
13. `%=` works on a local.
14. The same five operators work on an object field.
15. The same five operators work on an array element.
16. A field receiver with a side effect is evaluated once.
17. An array receiver with a side effect is evaluated once.
18. An array index with a side effect is evaluated once.
19. Assignment to an immutable local still fails.
20. A call expression remains an invalid assignment target.
21. Repeating index assignments 1, 16, and 64 times creates exactly three
    inner statements per assignment and one outer statement per assignment.
22. A qualified module call works when the importer only names module items.
23. A qualified call with a module class argument uses the same resolution.
24. `Map::new()` in a field assignment uses the declared field type.
25. `Channel::new()` in a field assignment uses the declared field type.
26. An empty array in a field assignment uses the declared element type.
27. `self.field += value` in a constructor remains visible to field-flow
    analysis after the field has been initialized.

The qualified-call and contextual-constructor paths already passed the original
reproductions on the starting tree; this session added regression tests for
their original acceptance conditions. The diagnostic span, raw newline, and
compound assignment needed source changes.

## Implementation audit

The lexer consumes each byte once. The diagnostic change substitutes the
parameter's existing type span and adds no analysis pass. Compound assignment
expansion is constant size: a local has one binary read and one write; a field
captures its receiver once when needed; an index captures its array and index
once each. Its generated branch and at most two temporary bindings are constant
per statement. With source length `N` and `A` compound assignments, parser time,
AST size, and generated code size remain `O(N + A)`; the 1/16/64 statement test
checks the deterministic expansion count. At runtime a compound assignment
performs one receiver evaluation, one index evaluation, one old-value read, one
RHS evaluation, and one store. No repeated scan or allocation grows with the
number of assignments beyond the necessary per-statement work.

The expansion uses an always-true scoped branch to keep compiler-generated
temporary names out of surrounding scopes. This adds constant branch overhead
for field and index forms. `self.field` uses the direct assignment path so
constructor field-flow analysis still sees it. The backend may fold the branch;
no wall-clock claim is made here. The current examples do not exercise every
generic element type or every async suspension shape.

Linux focused tests, formatting, Clippy for the Linux, Windows, and two macOS
CI targets, and the runnable example are the local gates. macOS and Windows
execution requires CI after a reviewed commit and push; local compilation
alone cannot prove their runtime behavior. Full
workspace tests and the full runnable-example audit were not requested locally.
